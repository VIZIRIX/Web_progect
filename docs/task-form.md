# ДОДАТОК D — БЛАНК ЗАВДАННЯ НА КУРСОВИЙ ПРОЄКТ

## 1. Тема проєкту

Бронювання переговорних кімнат

## 2. Конкурентна операція

Створення броні на інтервал. Два бронювання однієї кімнати з перетином часу
неможливі.

## 3. Зміст пояснювальної записки

- вступ;
- аналіз предметної області та технічне завдання;
- проєктування інформаційної системи;
- програмна реалізація вебзастосунку;
- тестування та розгортання;
- висновки;
- список джерел;
- додатки.

## 4. Перелік графічного матеріалу

- ER-діаграма;
- схема застосунку (app.ts → routes/services);
- діаграма послідовності ключових операцій (createBooking: lock → checks →
  create occurrences);
- знімки екрана інтерфейсу (auth, календар, бронювання) — після деплою.

## 5. Технічне завдання (з чату)

### Тема

Внутрішній сервіс компанії: кімнати, обладнання, брони на інтервали.
Класична задача про перетин часових проміжків.

### Ролі

- Співробітник
- Офіс-менеджер
- Адміністратор

### Сутності

- Кімната, Бронювання, Користувач, Відділ, Обладнання, Повторюване бронювання

### Зв'язок М:М

- Кімната ↔ Обладнання; Бронювання ↔ Учасник

### Обсяг сидів

25 кімнат, 12 відділів, 100 співробітників, 1500 бронювань

### Функціональні вимоги

- Співробітник: календар кімнат на день і тиждень; бронювання вільного
  інтервалу з темою зустрічі; запрошення учасників; повторюване бронювання
  (щотижня); скасування або перенесення власної броні; пошук вільної комнати
  за місткістю й обладнанням.
- Офіс-менеджер: керування кімнатами, місткістю й обладнанням; блокування комнати
  на прибирання чи ремонт; примусове скасування броні з повідомленням; звіт
  завантаженості комнат.
- Адміністратор: керування відділами й правами; налаштування робочих годин і
  максимальної тривалості бронювання.

### Особливості реалізації

- Повторюване бронювання створює окремі записи на кожну дату (інакше неможливо
  скасувати одну зустріч із серії).
- Перевірка перетину — умова в запиті до бази з відповідним індексом.
- Робочі години й максимальна тривалість перевіряються на сервері.
