# ADR 004 — Каскадне видалення + заміна оборудовання (deleteMany+create)

## Статус: прийнято (2026-11-22)

## Контекст

- Бронювання пов'язане з `BookingParticipant[]` (M:N — використовуємо
  `onDelete: Cascade` у коді (Prisma 6 підтримує каскади на полях).
- `ROOM_EQUIPMENT`: заміна оборудовання комнати — ручна `deleteMany+create`.

## Розглянуті варіанти

1. Каскадне видалення через `onDelete: Cascade` — підтримується Prisma 6.
2. Ручне видалення усередині транзакції (сервіс) — залежить від порядку викликів.

## Рішення

- `BookingParticipant.userId/bookingId` — `onDelete: Cascade` (як у оригіналі).
- Заміна оборудовання комнати — `deleteMany + create` в одній транзакції (`room.service.updateRoom`).

## Наслідки

- Немає "бророфлоних" (сирих) учасників при видаленні.
- Клайент `DELETE /api/bookings/:id` — є каскад.
- Повторна операція безопасна: `deleteMany` чистить лишні ліхтарі.
